# Contributing to MetaSpici

Thank you for considering a contribution to MetaSpici. These rules apply to code, documentation, tests, data schemas, examples, workflows, designs, and other material submitted to the project.

For this document, the **Project Owner** is Southern University of Science and Technology. The **maintainers** are the people authorized by the Project Owner to manage the MetaSpici repository.

## Before contributing

- Open an issue before substantial work so that scope, scientific assumptions, interfaces, and validation can be discussed.
- Do not submit confidential information, personal data, controlled data, unpublished third-party data, credentials, or material subject to incompatible terms.
- Confirm that you created the contribution or have written authority to submit it under these terms.
- Identify any third-party code, generated code, model output, data, assets, or documentation included in the contribution, and provide its source, version, license, and required notices.
- Do not add or upgrade a dependency until its license and redistribution requirements have been reviewed and `THIRD_PARTY_NOTICES.md` has been updated where necessary.

## Technical expectations

Contributions should:

- be focused and accompanied by a clear explanation;
- include tests or reproducible validation appropriate to the change;
- preserve scientific traceability, including units, assumptions, parameters, random seeds, and data provenance where relevant;
- document user-visible behavior and compatibility changes;
- avoid committing large datasets, binaries, secrets, or personally identifiable information without prior approval; and
- pass the project's formatting, linting, test, and documentation checks.

## Review and acceptance

Contributions are accepted at the maintainers' discretion. Submission does not create an obligation to review, merge, publish, maintain, credit, or compensate a contributor. Maintainers may modify, reject, revert, or remove a contribution when necessary for scientific validity, security, maintainability, licensing, or project direction.

## Reporting issues

Use the GitHub issue tracker for reproducible bugs and feature requests. Do not disclose an unpatched security vulnerability or sensitive dataset in a public issue; use a private contact channel listed in the repository profile or release documentation.
